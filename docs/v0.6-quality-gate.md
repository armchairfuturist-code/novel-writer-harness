# v0.6: the quality gate

StoryForge v0.5 had real machinery — debate court, revision loop, style engine —
but the loop almost never ran: chapters started at a flat 7.0/10 and exited on
round 0, so the flagship debate feature fired only on chapters the regex had
already condemned, and a 165-word stub could outrank a 4,000-word chapter on
style alone. Nothing was persisted, so no score could trend.

v0.6 adds a deterministic, model-free prose gate that runs in front of every
expensive judge call, plus revision memory so a defect fixed in chapter 3 does
not recur in chapter 20.

## What changed

**`pipeline/prose_lab.py` (new)** — a stdlib-only instrument scoring each
chapter 0-10 with explainable violations, each carrying its own fix:

- tell/arrival/cliche/overcompletion rules (rates per 1,000 words against
  bands; taxonomy from Compound Writing's tracks/ai-check skills, rules written
  for this repo)
- rhythm, rarity (type-token/hapax — the longtail insight: low rarity is the
  dense-cluster signal), and dialogue-share bands
- bands fitted on the manuscript's own chapters (`bands_from`/`drift`), so
  voice consistency across 300 pages is a number, not an opinion
- CLI exits 1 below threshold (`LLM_MIN_PROSE_SCORE`, default 7.0) — CI-usable,
  like longtail's stylo contract

**`pipeline/revision_memory.py` (new)** — append-only JSONL of per-chapter
defects; `top_recurring` surfaces the repeated ones into later chapters'
drafting prompts (Compound Writing's save routing, applied to memory_store).

**`pipeline/draft.py`** — composite score (mechanical 0.45 + prose 0.55, minus
length floor so stubs can't win), revision loop triggers on score below floor
OR prose gate fail, debate decouples from the regex gate, revision acceptance
requires improvement or fewer prose violations without shrinking, variant
selection enforces a word-count floor relative to the chapter target.

**`config.py`** — new `ProseConfig` (`min_prose_score`, `min_variant_word_ratio`,
overridable via env).

**`storyforge.py`** — writes `quality/quality.json` after the draft phase:
per-chapter scores plus aggregate, trendable.

**CI** — workflow now triggers on `master` (the default branch was never
watched), and a `prose-gate` job runs the instrument over `reference/chapters`.

## What was deliberately not done

No model calls, no nltk/scipy (EQ-Bench's metrics need them — cited as
reference, not vendored), no vendor of Compound Writing or longtail text
(neither project ships a license; their mechanisms are reimplemented here and
credited). The gate measures "not machine-slop" and "matches the plan" — never
"good". Pairwise Elo remains the right tiebreak where rubrics saturate.

## Running

    python -m pipeline.prose_lab chapter-003.md
    # exit 1 below 7.0/10 with per-rule fixes quoted

    python -m pipeline.prose_lab --bands reference/chapters/*.md
    # per-manuscript bands + drift report

## Roadmap (from the CW / longtail / field surveys, not yet built)

- fiction shape-card sampler feeding the chapter planner (fight template
  collapse across 60 chapters)
- per-narrator voice profile refit on fiction prose, plus longitudinal drift
- temporal story bible (facts carry chapter intervals; post-chapter extraction
  writes back)
- foreshadowing as a four-state scheduler (planted/reinforced/paid off/
  abandoned)
- outline cascade revision and a benchmark eval harness whose detectors are
  refit on this repo's own output so the score cannot be gamed
